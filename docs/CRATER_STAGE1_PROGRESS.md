# The Crater — stage one implementation

Branch: `plan/crater-creatures-and-skilling-pets`. No merge or deployment.

The user has authorised continuing branch development and explicitly allowed goblins to throw rocks that damage the player. This resolves the earlier melee-only conflict. The approved miner remains a cautious thrower; the guard's cleaver/shield design remains unchanged. This stage does not invent guard throwing artwork.

## Implemented

- `crater-definitions.js`: immutable approved roster of eight hostiles, five wildlife and three skilling pets, with final names/levels, reference-board identities, behaviours and the summoned-only matching 3% bonus contract. Missing production balance and atlas files are explicitly `null`; this registry does not replace existing live actors.
- `crater-rocks.js`: bounded projectile simulation with captured aim, swept player contact, obstruction checks in contact order, finite range, one impact per projectile, invalid-input guards and lifecycle clearing. No combat XP, item rewards or animation-timed damage is generated by this module.
- The game has an explicit `?craterPreview=1` development switch. On the branch build only, existing legacy goblins prepare, throw damaging rocks and retreat at close range. Player movement after the windup can dodge the captured trajectory. Existing enemy damage, armour reduction and cooldown data are reused. Windup/range/speed values in `ROCK_PREVIEW` are provisional mechanics tuning, not approved final balance.
- Normal play does not create projectiles or enable this preview behaviour. A visible preview label identifies the old goblin art; it is not presented as the approved miner sprite or a finished Crater encounter.
- The preview uses a separate local save key, does not read/write the normal IndexedDB save, disables cloud save reads/writes and room presence, and clears transient rocks on scene changes, death and save restore. Normal mode keeps its current save key and persistence paths.
- Existing melee damage and rock impacts share one damage calculation. Both existing player attack/reward paths remain unchanged.
